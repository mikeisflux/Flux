# Flux — Skills Catalog

Transcribed from the Polar reference screenshots, `Templates › Skills`.

## What a Skill is (vs. a Task)

Page subtitle, verbatim:

> **Reusable know-how Polar draws on automatically when it's relevant. Add a
> skill to make it yours.**

This is the clearest statement of the two-layer model:

| | **Task** | **Skill** |
|---|---|---|
| What it is | A runnable job | Reusable know-how |
| Invocation | User picks and runs it | **Drawn on automatically when relevant** |
| Description style | Names the *artifact produced* ("A deduped tracker sheet…") | Names the *capability* ("Screen an NDA against standard carveouts…") |
| Schedulable | Yes — ~40% ship a schedule | **No** — no schedule chip on any skill card |
| Personalizable | Fill in the prompt | **"Add a skill to make it yours"** — a fork/customize action |
| Count | 250 | 117 |

So: Tasks are the *verbs*, Skills are the *competence* the agent brings to any
verb. A task like "Vet a company's legitimacy before you sign or pay" would
pull in the `Regulatory compliance check` and `Contract review & redlining`
skills without the user asking.

## UI differences from the Tasks screen

Same three-column shell, same card grid, but:

1. **No facet row.** Tasks has `For Everyone ⌄` and `⟳ Scheduled`; Skills has
   neither — the filter area is just the category chips.
2. **No Monitoring chip.** Task categories are: All, Sales, Recruiting,
   Marketing, Data, Research, Ops, Engineering, Docs, Personal, Monitoring.
   Skill categories drop Monitoring — 10 chips, not 11. Consistent with
   monitoring being a *scheduling* property, which skills don't have.
3. **No schedule chips** on any card.
4. **No Featured section.** The page opens directly on Sales.
5. Search placeholder is `Search skills, sites, roles...` (vs. `tasks`).
6. Card footer carries connector icons only, so many cards have an empty
   footer — pure-reasoning skills (`System design`, `Compensation Analysis`)
   touch no third-party service at all.
