## Patterns worth encoding

Observations that should drive Flux's own template schema:

1. **Every description names a deliverable, never a process.** "A deduped
   tracker sheet…", "Gmail drafts ready for review…". The schema should have a
   required `outcome` field, not a `description`.
2. **Write-safety is stated in prose, never structurally.** "left unsent",
   "ready to review", "staged for your final click", "Nothing sends without
   you." Polar is clearly careful here but encodes it only in copy.
   → **[FLUX]** make it a required enum: `readonly | draft | send | purchase`,
   rendered as a badge and enforced by the agent's approval gate.
3. **Schedules are natural-language, not cron.** "Twice a day, 8am and 5pm",
   "Mondays and Thursdays at 8am", "Every 3 hours". Store cron, render prose.
4. **Connector list is derivable from the tools a task uses** — it shouldn't be
   hand-maintained metadata.
5. **Same template appears in multiple sections** (Featured + Sales). Category
   is a tag set, not a single parent.
6. Roughly **40% of templates ship with a schedule**, which is what makes the
   task→workflow promotion the core loop rather than a side feature.
